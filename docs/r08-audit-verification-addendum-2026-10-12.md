## Per-item evidence and closure criteria

### A01 — STILL OPEN: URL/upstream exposure remains

**Verified:** [Forms loader](../src/lib/va/forms-finder.ts#L53-L159) rejects inputs consisting of at least eight digits after common separators are removed, before cache/upstream work, and does not echo the rejected value. Newly cacheable views contain `query: ""`; caller display text is reattached after cache access. The [locator](../src/lib/va/accredited-representatives.ts#L86-L146) similarly stores an empty ZIP in cached lookup params and reattaches request params for display. Its radius/type remain cached, and returned directory records legitimately contain representative ZIPs; this is not removal of every ZIP from the response. [Identifier tests](../tests/va-forms-finder-identifier-rejection.test.ts) and [cache-value redaction tests](../tests/va-reference-cache-value-redaction.test.ts) pass.

**Remaining (as reviewed):** the [Finder page](../src/app/va-forms/finder/page.tsx#L35-L42) was still a GET form accepting arbitrary bounded text. The adjacent warning accurately names URL/history exposure, but rejection cannot remove an identifier from the request URL already received. Mixed text is intentionally outside the identifier guard and can reach VA when enabled. Hashed low-entropy keys are not anonymity; fresh redacted writes do not prove old stored entries were purged. Host/CDN retention, query scrubbing, and ZIP-lookup retention have not been verified.

**Update 2026-10-12 — the finder's URL exposure is closed.** The search is now a Server Action ([`searchVaFormsFinder`](../src/lib/actions/va-forms-finder.ts)) whose text travels in the request **body** through the [PHI-free action-input contract](../src/lib/security/phi-free-action-input.ts) and returns the view as action state. The [page](../src/app/va-forms/finder/page.tsx) reads no query parameter, so a stale `?q=` bookmark is inert rather than a second transport, and the [rendered surface](../src/components/va/VaFormsFinder.tsx) performs no client navigation and no history rewrite. A reference-path POST is charged to the shared reference-read budget in [`src/proxy.ts`](../src/proxy.ts) (verified behaviorally, not by inspection), because otherwise the change would have moved the search off admission control as well as off the URL. Synthetic evidence: a mounted submit asserts the text reaches the action's `FormData` while `window.location`/`document.URL` never contain it; an over-long query returns a fixed `oversized-value` code with no echo of the value in the state or in captured console output; and a canary search shows no copy of the text outside the visitor's own display echo. **Update 2026-10-12 (second pass) — the locator's URL exposure is closed too.** The accredited-representative search is a Server Action ([`searchAccreditedRepresentatives`](../src/lib/actions/accredited-representatives.ts)) that validates through the same [PHI-free action-input contract](../src/lib/security/phi-free-action-input.ts), checks the whole POST body for PHI-shaped field names, and returns the directory view **as action state** instead of redirecting with `?zip=&radiusMiles=&type=`. The three hosting pages ([`/secondary/suggestions`](../src/app/secondary/suggestions/page.tsx), [`/secondary/evidence`](../src/app/secondary/evidence/page.tsx), [`/presumptive/results`](../src/app/presumptive/results/page.tsx)) therefore read no lookup query parameter and no longer load the directory view server-side, the surface ([`AccreditedRepresentativeFinder`](../src/components/va/AccreditedRepresentativeFinder.tsx)) performs no navigation or history rewrite, and the URL-parameter error reader that fed the retired `?error=` transport was deleted with its transport. `returnTo` survives only as an allowlisted audit-event label and is never concatenated into a URL (pinned behaviourally: a crafted `returnTo` is replaced before it reaches the sink). Reference-path POSTs were already charged to the shared reference-read budget in [`src/proxy.ts`](../src/proxy.ts), so the lookup did not move off admission control. Synthetic evidence: [`tests/va-accredited-rep-no-url-exposure.test.ts`](../tests/va-accredited-rep-no-url-exposure.test.ts) pins no-redirect/no-URL-building plus the fixed refusal codes and the absence of any echo; [`tests/va-accredited-rep-locator-surface.test.tsx`](../tests/va-accredited-rep-locator-surface.test.tsx) drives a mounted submit and asserts the ZIP reaches the action's `FormData` while `window.location`/`document.URL` never contain it; and `e2e/secondary-workflow.mjs` now asserts the results render **in place** with no `zip=` in the URL (it previously asserted the redirect, which is what made the redirect un-removable without a journey update).

**Still open:** the upstream VA requests (Forms search text and directory ZIP) still carry the lookup text as a query parameter by design, and host/CDN retention plus old-entry purging remain operator evidence ([#537](https://github.com/richardparslow-commits/Secondary_Condition_Finder/issues/537)).

**Close when:** reduce/constrain URL and upstream input exposure or record explicit reviewed risk acceptance, and verify retained request-log/cache behavior, including old entries, with synthetic evidence. Operator review remains with [#537](https://github.com/richardparslow-commits/Secondary_Condition_Finder/issues/537); [#538](https://github.com/richardparslow-commits/Secondary_Condition_Finder/issues/538) specifically owns OAuth callback scrubbing, not an automatic proof that arbitrary Finder queries are scrubbed.

### A03 — STILL OPEN: fixed-window and command-validation risks persist

[Consumer reservation](../src/lib/va/reference-shared-cache.ts#L497-L525) still uses `floor(now / 60000)` with 60 admissions and a separate 120-second key expiration. Synthetic calls to the actual function reproduced **60 admissions at 59,999 ms + 60 at 60,000 ms = 120** across adjacent buckets. This is a counter-semantics observation, not a timing benchmark or proof of an issued VA quota violation. The function also accepted a synthetic fractional `INCR` result of `1.5`, and returned admission after an `EXPIRE` body error. It checks finite-positive counts, not safe integers, and does not inspect the expiration result. Quota reset/remaining headers do not adapt this pacing.

**Positive control:** [adapter admission](../src/lib/va/sandbox.ts#L414) runs inside the attempt loop; retry-reservation tests pass. [Runtime guidance](va-api-runtime-configuration.md#shared-state-is-a-separate-activation-prerequisite) requires all instances for a consumer to share the correct store/prefix and requires deployment verification. That guidance does **not** establish the issued consumer's rolling/fixed/reset semantics.

**Close when:** confirm VA quota/reset policy and consumer/environment/credential-sharing key scope, then implement compatible conservative pacing or atomic sliding/token admission and strict command-result validation. [#287](https://github.com/richardparslow-commits/Secondary_Condition_Finder/issues/287) owns operator activation evidence, but this finding is **not external-only**: fractional-result and expiry handling are repo-controlled work.

### A04 — CLOSED (2026-10-13): every tier applies the loader's own DTO

[Guard](../src/lib/va/cached-view-guard.ts#L92-L136) now rejects non-array `items` and unparseable non-null retrieval dates. Label/environment, HTTPS-without-credentials, item-count, and node-count checks exist; [guard tests](../tests/va-cached-view-guard.test.ts) pass.

**Reproduced residue:** a live-labelled view with `items: [null]`, or an item with an object-valued title and an arbitrary credential-free HTTPS host, still passes. This does not prove the Finder can render it safely. Per-loader DTO fields, lookup binding, official-host provenance where applicable, exact copy, and single-form revision-date validity are not fully checked. Null retrieval timestamps remain allowed. [Cache access](../src/lib/va/reference-cache-access.ts#L148-L190) guards shared hits and contender-published hits, **not process-local hits or fresh writes**. No claim is made that every tier applies validation.

**Update 2026-10-13 — shared-read DTO/lookup residue closed.** All five loaders now apply [per-loader strict Zod cache DTOs](../src/lib/va/cached-view-guard.ts) before either an ordinary shared hit or a contender-published hit is served/promoted. DTOs require the exact surface/environment provenance copy, a non-null valid ISO retrieval timestamp on live-list views, the actual item fields/types, bounded strings/URLs/numbers/nested specializations, and bounded lists (25 Forms Finder items; 200 for the other lists). Single-form metadata is restricted to `21-526EZ` and validates calendar revision dates. These are application cache limits, not claims about VA API limits.

The Forms Finder and locator store `lookupKey` equal to the requested cache key (which already hashes normalized search text or ZIP/radius/type), and validate it as an exact literal. Finder `query` must remain empty; locator `params.zip` must remain empty while radius/type exactly match the request's effective defaults. Old entries without the binding miss until refreshed. No raw query or lookup ZIP is restored to cache values; caller display inputs are still reattached only after cache access. A hash is neither anonymity nor cryptographic authenticity. The representative loader projects provider results onto the known DTO fields instead of retaining arbitrary upstream extras.

[Behavioral regression tests](../tests/va-cache-dto.test.ts) exercise every loader through the actual shared-envelope reader and cache-access/single-flight paths: valid hits avoid upstream calls and promote; malformed items, unknown fields, wrong bindings/params, invalid dates/provenance, and oversized fields/lists refetch or return an uncached fallback without promotion. Fresh writes round-trip through their own shared-read DTOs, and explicit/omitted default locator params share the correct hit. The original reproduction paragraph above describes the pinned review, not the current shared-read behavior.

**Update 2026-10-13 (second pass) — the remaining three boundaries are closed.**

*Every tier, one rule.* [`withVaReferenceCache`](../src/lib/va/reference-cache-access.ts) now takes a single `cacheTrust` policy per loader — `accepts` (the loader's DTO) plus `degradedView` (what it serves instead) — and applies it to the **process-local hit**, the shared hit, the contender-published hit, and the loader's **own fresh view before either write**. A rejected process-local entry is deleted so later requests are misses rather than re-validating a known-bad value on every call, and an out-of-bounds fresh view becomes the loader's labelled local fallback (`live:false`, `environment:null`, its own notice) instead of being rendered as live VA data. Requiring `degradedView` alongside `accepts` is what makes "a loader cannot validate without also saying what it serves instead" structural: the old read-side-only hook could reject a value on the shared path and serve the identical value as live on the local path, which is precisely what the previous slice left open. Each rejection is disclosed through the reviewed logger clients as an `outcome`-coded operational line with no cached value, lookup key, or search text ([inventory](../tests/logging-sink-inventory.test.ts)).

*Loader-specific link origin.* Form metadata — a VA Forms item URL and the single-form reference URL — must be a credential-free HTTPS URL **on an official VA host** (`isTrustedVaOfficialUrl`, `va.gov` or a subdomain), because a rendered link is the one cached field a reader clicks and a credential-free third-party destination was previously accepted. The directory keeps the structural rule deliberately: a VSO's or attorney's own site is legitimately outside va.gov, so `isTrustedCachedLiveView` cannot require a VA host and the per-loader DTOs carry the distinction. The rule is enforced in the cache DTOs rather than in the upstream payload schema so one unusual item degrades its own surface instead of failing an entire VA response.

*Envelope alignment, measured.* The write bound is no longer a separate number: `vaSharedCacheReplyBytes(value, epoch)` projects the JSON re-wrapping the reader actually parses (a stored envelope comes back inside a `{result:[epoch,value]}` string, so quotes and backslashes cost extra bytes), and a write is admitted only when that projection fits `VA_SHARED_CACHE_MAX_REPLY_BYTES` (64 KiB, the reader's own cap) minus `VA_SHARED_CACHE_REPLY_RESERVE_BYTES` (512, for reply framing the projection does not model). The historical **256 KiB serialized write vs 64 KiB command-reply read** pair is gone: a value the reader would drop as oversized is refused before any `SET`, so the store no longer accepts values it will never return. Version/epoch markers remain consistency checks, not cryptographic writer authentication, and the reader still fails closed on an oversized or hostile reply it did not write.

**Evidence:** [tests/va-cache-boundary-trust.test.ts](../tests/va-cache-boundary-trust.test.ts) drives all five real loaders through the real cache-access, shared-envelope, and single-flight paths for: a forged process-local entry its DTO rejects (loader refetches, entry deleted, no request leaves the process); a fresh out-of-bounds upstream view (labelled fallback, neither tier written, no value `SET`); the positive controls that the same loader's own valid write is served locally without a second upstream call; the VA-host rule accepting `www.va.gov` and `www.vba.va.gov` while rejecting `collect.example.org`, `notva.gov.evil.example` and `va.gov.attacker.example`; the directory still accepting an external VSO site while rejecting HTTP, credentials, and `javascript:`; a binary-searched boundary value that round-trips through the shared store at the write budget while one byte more is refused; and a hostile oversized reply that a reader refuses. The [guard suite](../tests/va-cached-view-guard.test.ts) and the [shared-read DTO suite](../tests/va-cache-dto.test.ts) gained the off-host-link cases, and [tests/va-shared-reference-cache.test.ts](../tests/va-shared-reference-cache.test.ts) had one synthetic fixture (a form link to `https://x`) corrected to a real VA-hosted URL.

**Close criterion met:** loader-specific schema/lookup/link/date bounds are enforced at every trust boundary and the read/write envelopes are aligned with measured overhead, with invalid candidates becoming misses or labelled fallbacks rather than rendered live data.

**Retained (not waived):** envelope versions/epochs and lookup hashes are consistency checks, not cryptographic writer authenticity; a rejected *fresh* view degrades the whole surface for that request rather than dropping only the offending item; and the pre-change reproduction in the pinned review stands as a description of `276c0d88`, not of current behaviour. No public arbitrary cache writer, actual XSS, or real corrupted production entry was demonstrated.

### A06 — CLOSED (2026-10-13): every clause of the close criterion is met and tested

**Verified improvements (this was the state at the pinned review):** [DD-214 analyzer](../src/components/presumptive/Dd214LocalAnalyzer.tsx#L89-L255) records textless pages and OCRs them even when other pages contain text. It reports page/text limits, bounds retained PDF segments, caps PDF canvas area through [shared sizing](../src/lib/evidence/ocr-session.ts#L74-L112), releases canvases/pages, probes worker health, and terminates workers/tasks in finally blocks. Generation/cancel/unmount checks exist; [resource](../tests/dd214-local-analyzer-resource-controls.test.ts), [cleanup](../tests/dd214-local-analyzer-cleanup-contract.test.ts), and [OCR primitive](../tests/ocr-session-memory-limits.test.ts) tests pass. The [preview](../src/components/presumptive/Dd214LocalAnalyzer.tsx#L668-L671) qualifies redaction as common SSN layouts and warns about unusual OCR spacing; user confirmation is required before persisting service history.

**Then-remaining (this is what the pinned-`276c0d88` review recorded):** [direct-image OCR](../src/components/presumptive/Dd214LocalAnalyzer.tsx#L257-L270) still sent the file without a decoded-image dimension cap or job deadline. Logical cancellation/finally blocks did not promptly terminate a hung awaited worker/task; bounded retained text was not bounded transient decode/text-layer memory. Mixed text/OCR segments were collected in separate passes, not guaranteed original page order. The parser [ignored `_limits` and sliced at 200,000 characters](../src/lib/evidence/dd214-extract.ts#L170-L197), silently below the analyzer's 500,000-character standard budget. Synthetic probes confirmed caller `textChars: 10` is ignored, February 31 is emitted as an ISO-shaped date, and uncommon SSN punctuation survives in raw preview text.

**Update 2026-10-13 (first pass) — parser and retained-text residue closed.** [`parseDd214Text`](../src/lib/evidence/dd214-extract.ts#L199-L242) now slices at the caller's `textChars` (nonsensical budgets are treated as *no* text, never as unlimited) and discloses truncation with the exact count instead of stopping silently at a private constant. [`toIso`](../src/lib/evidence/dd214-extract.ts#L106-L124) validates real calendar dates against month lengths and the century leap rule, so `02/29/2021`, `02/31/2020`, and `02/29/1900` are dropped rather than emitted as ISO-shaped dates; a surviving date in the same document still parses, and a single date becomes the start only. SSN minimization is one shape — three digits, two digits, four digits separated by **any run of up to three non-digit characters** (hyphen, space, dot, underscore, en/em dash, NBSP, or nothing) — instead of a list of layouts, so `123.45.6789`, `123–45–6789`, and `123_45_6789` no longer survive in the retained preview, while `(555) 123-4567` and ISO dates stay readable by construction. The analyzer assembles per-page text **in page order** through [`assemblePageOrderedText`](../src/lib/evidence/ocr-session.ts#L428-L467) under the review budget, so a mixed PDF is the document's prefix rather than whichever pass ran first. [Behavioral suites](../tests/dd214-extract-bounds-and-dates.test.ts) (18 cases) and [primitive bounds](../tests/dd214-image-decode-bounds.test.ts) (12 cases) assert each of these against the real functions; the 200,000-character slice, the day ≤ 31 check, and the layout list each fail their own case if restored.

**Update 2026-10-13 (second pass) — decode bounds, elapsed work, and prompt teardown closed.**

*Bounded before decode.* [`planImageDecode`](../src/lib/evidence/ocr-session.ts#L394-L432) reads the declared dimensions out of the container header itself — PNG, JPEG (SOF), GIF, BMP (including top-down), WebP (VP8X/VP8L/VP8), and TIFF (both endians, bounded IFD scan) — with **no decode and no allocation**, and refuses a bomb-shaped or unmeasurable input (`too-many-pixels`, `dimension-too-large`, `unknown-dimensions`) before any bitmap exists. An accepted image renders through the same `computeOcrRenderMetrics` canvas-area cap the PDF path uses, the decoded bitmap is closed in a finally, and the refusal names the measured size so the Veteran can act on it. The analyzer no longer hands the raw `File` to the worker on the accepted path.

*Bounded elapsed work.* [`startOcrJobDeadline`](../src/lib/evidence/ocr-session.ts#L143-L190) arms a five-minute budget whose expiry terminates the live worker and loading task, so a `recognize()` promise that never settles rejects and the run unwinds through its normal finally chain — the case a per-page boundary check cannot reach, because a hung await never returns to the boundary. The callback is isolated (a throwing teardown cannot defeat the budget) and the timer is unref'd so it cannot keep a Node process alive.

*One teardown, once.* Cancel, the deadline, and unmount all route through `terminateActiveRun()`, and worker teardown is owned by a single guarded helper (`finishWorker`) so a worker already terminated by cancel/deadline/unmount is not terminated a second time inside a finally — a second `terminate()` can reject there and mask the outcome it was cleaning up after. The pdf.js task is destroyed under the same once-only rule, and the deadline path reports its own stop and clears busy state instead of leaving the surface stuck. This was found by the new mounted suite: the once-only assertion read **2** terminate calls against the pre-fix component, which is what exposed the double teardown.

**Behavioural evidence — mounted, not source order:** [tests/dd214-image-decode-bounds-mounted.test.tsx](../tests/dd214-image-decode-bounds-mounted.test.tsx) (6 cases) mounts the real component and drives it through the file input with pdf.js and the Tesseract factory faked: a 10,000 × 10,000 header is refused with its measured size, **zero** worker creations, zero `recognize` calls, no `createImageBitmap`, and no storage write; an unmeasurable container is refused by message rather than by guess; an accepted 4,000 × 3,000 image reaches `recognize` as a **bounded canvas** (never the `File`), within the shared pixel-area cap, with the downscale disclosed and the canvas released to 0 × 0; a hung `recognize()` is stopped by the elapsed-work budget (one terminate, the limit message, the Cancel button gone); Cancel tears the live worker down, reports cancellation, commits nothing, and does not also report a deadline stop; and a mixed 3-page PDF (text, textless, text) retains `TEXT PAGE ONE → OCR PAGE TWO → TEXT PAGE THREE` **in page order** in the retained preview while warning that one page was OCR'd. The [structure suite](../tests/dd214-local-analyzer-resource-controls.test.ts) grew to 13 cases pinning the same wiring, and the [cleanup contract](../tests/dd214-local-analyzer-cleanup-contract.test.ts) was re-aimed at once-only teardown (one `await worker.terminate()` in the codebase, owned by the guarded helper and called from all three finally blocks; one conditional `task.destroy()`).

**Close criterion met:** image decode/transient allocations and elapsed work are bounded, teardown is prompt and once-only, page order is preserved, the parser honors and discloses its limits, dates are validated against a real calendar, and preview minimization is tested by case rather than claimed — with the retention claim qualified in the UI.

**Retained (not waived):** the mounted suite is jsdom with faked pdf.js/Tesseract, not a real-browser run, so an actual image-bomb, mixed-PDF, or hung-WASM incident in Chromium/Safari remains unmeasured; calendar parsing stays heuristic (downstream validation and the mandatory user confirmation remain distinct safeguards); the effect of the 40 MP / 20,000-px ceilings on a legitimate very-high-resolution scan is a usability judgement, not a correctness proof; and nothing here is evidence of server transmission — the DD-214 path is browser-local and writes no checkpoint.

### A07 — CLOSED (2026-10-12): write fencing completed and behaviourally tested

**Remediated in the same session that filed the gap, against the criterion below.** [Chunk checkpoint path](../src/components/evidence/LocalEvidenceAnalyzer.tsx#L640-L652) re-checks the extraction generation **after** `await yieldToBrowser()` and before `saveOcrCheckpoint`, so a run suspended across that boundary cannot recreate a checkpoint that cleanup just removed. [`analyzeOneFile`](../src/components/evidence/LocalEvidenceAnalyzer.tsx#L343-L370) now takes the caller's generation predicate and returns uncommitted after its awaited extraction — the internal commit is fenced, which a caller-side check after the call could not achieve. Evidence persistence left the React state updater ([`applyAnalyses`](../src/components/evidence/LocalEvidenceAnalyzer.tsx#L156-L162) plus a mirrored ref): a storage write inside an updater runs once per invocation and React may invoke it more than once, measured as **2 writes for 1 analysis** under StrictMode, now **1**. Unmount terminates the in-flight OCR worker and destroys the PDF loading task, so the completion controls stop recognition immediately rather than at the next page boundary, while the run's own finally chain still performs the ordinary teardown.
